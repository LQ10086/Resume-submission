# 投递文本助手

这是一个本地运行的 Windows 桌面小工具，用来管理投递表单里反复填写的文本。你可以把姓名、联系方式、实习经历、科研经历、项目描述等内容提前写进 JSON 资料库，然后在投递网页里点击输入框，再点本工具里的快捷按钮。

## 直接使用

如果已经打包成功，双击运行：

```powershell
release\ResumeQuickPaste.exe
```

发布版面向 Windows 10/11 64 位系统，Python、PySide6/Qt、终端渲染器等运行依赖已包含在 exe 中，其他电脑无需安装 Python 或 Qt。Office、WPS、LibreOffice 和编辑器不会被打包；程序会在每台电脑上动态读取该机的 32/64 位应用注册信息，因此“打开方式”只显示该机实际注册的应用。注册表信息缺失或损坏时，菜单仍会保留 Windows 系统“选择其他应用”。

程序优先把 `databases` 和 `app_settings.json` 保存在 exe 同级，便于整包复制。若 exe 位于 `Program Files` 等当前用户不可写的目录，会自动改用 `%LOCALAPPDATA%\ResumeQuickPaste`，首次使用时只复制随程序附带的资料库，不覆盖已存在的数据。需要指定数据位置时，可以在启动前设置环境变量 `RESUME_QUICK_PASTE_HOME`。

源码版已经迁移到 PySide6，所有 Python 运行代码统一放在 `src` 目录。首次双击 `run.bat` 时，`setup_pyside6.ps1` 会在项目内创建隔离的 `.python-runtime`，使用 python.org 便携版 Python 3.13 和锁定的 PySide6 6.10.1，不修改系统默认 Python，也不依赖本机 Conda。旧 Tkinter 实现在 `src/legacy_tk_app.py` 中保留作迁移参考；迁移前 Git 回退点为本地分支 `backup/pre-pyside6-20260822`。

使用流程：

1. 先在浏览器或招聘系统里点击需要填写的输入框。
2. 回到本工具，点击快捷按钮。
3. 默认情况下，程序会把文本复制到剪贴板并选择该条目，不会自动粘贴。
4. 如果勾选“点击后自动粘贴”，普通点击会尝试粘贴到刚才的输入框。
5. 如果保持默认关闭自动粘贴，按住 `Ctrl` 再点击快捷按钮，会临时强制自动粘贴。
6. 按住 `Shift` 点击快捷按钮可以只选择条目，不复制也不粘贴；连续 `Shift+点击` 可多选，用于批量删除。
7. 在同一分组内拖动条目并松开，可以按蓝色插入线调整到任意位置；拖到其他分组的指定位置可以同时换组和排序，拖到卡片外仍会尝试模拟键盘输入。
8. 条目卡片完整显示类型和键名，不再按固定字符数截断；较长名称会占用相应宽度并由流式布局自动换到下一行。
8. 资源条目按住 `Ctrl` 点击只复制路径；按住 `Ctrl+Shift` 点击会直接打开文件或网址；再同时按住资源管理器定位快捷键和左键，会在资源管理器中定位文件或打开文件夹。
9. 资源条目右键可按 Windows 默认方式打开、打开所在文件夹，或从系统已注册应用中选择“打开方式”；所有条目仍可编辑、复制、分组和删除。
10. 选中一个条目后使用组内移动快捷键，可以在当前分组内向左或向右移动一格；按 `Ctrl+↑` 或 `Ctrl+↓` 可以把该条目所在的整个分组向上或向下移动一格。
11. 按 `Ctrl+N` 可以随时打开“新增条目”窗口。

顶部的“窗口置顶”默认开启，适合单屏投递时让工具一直浮在网页上方。你也可以关闭它，让窗口按普通方式切换。

“点击后自动粘贴”默认关闭。这样普通点击不会误填到网页里；需要临时自动粘贴时，按住 `Ctrl` 再点击快捷按钮。

## 终端与设置

- 顶部“设置”菜单可以打开设置窗口，也可以直接打开终端。
- 右侧区域包含“终端”和“信息”两个标签页。点击左侧任意条目会自动打开“信息”页，可直接修改键名、分组、条目类型和内容并保存；“弹窗编辑”仍保留原有编辑窗口。
- 默认快捷键是 `Ctrl+J`：第一次按下显示终端，再次按下隐藏终端；快捷键可在“设置 → 快捷键”中点击“更改快捷键”，然后直接按下新的组合键识别保存。
- “设置 → 快捷键”可以分别修改打开/隐藏终端、新增条目、编辑条目、搜索、名称查找替换、组内左右移动、分组上下移动和资源管理器定位快捷键。
- `Ctrl+F` 聚焦顶部搜索框并全选现有关键词，可搜索条目名称或内容；`Ctrl+R` 打开“查找并替换条目名称”，实时显示命中数量并支持批量替换。替换后若名称为空或发生重名，程序会在写入 JSON 前阻止操作。
- 设置窗口的“快捷键”“终端”“外观”页均支持鼠标滚轮和右侧滚动条；切换标签后滚轮只滚动当前页，底部保存/取消按钮保持固定。
- 终端默认使用 PowerShell，工作目录默认是相对项目目录的 `tmp`；程序会自动创建该目录。打包版如果位于项目的 `release` 文件夹，会优先使用项目根目录下的 `tmp`，便于源码版和打包版共用。
- “设置 → 终端”可以切换 PowerShell/CMD、修改默认路径、终端字体和字号，并设置终端启动后自动输入的命令；默认命令是 `codex`，需要时可以清空。新设置优先使用 Cascadia Mono；如果目标电脑没有该字体，Qt 会自动回退到 Cascadia Code、JetBrains Mono、Consolas 或系统等宽字体。
- 终端使用与主界面一致的主题和等宽字体；默认停靠在主界面右侧，也可以在“设置 → 终端 → 停靠位置”切回底部。拖动分隔条时先显示位置预览，松开后再一次性重排内容；终端尺寸同步也会自动合并，避免左右调整宽度时卡顿。关闭终端面板不会结束终端进程，退出主程序时会结束该终端进程。
- 终端光标按实际显示列定位，中文、Emoji 等双宽字符不会再导致光标与输入末尾逐渐错位。
- 终端使用独立绘制的固定输入光标；鼠标移动、点击和选择文字不会把命令光标带走。已接入 Windows 输入法事件，可直接使用拼音等输入法完成中文预编辑和提交。
- ConPTY 输出通过 pywinpty 的完整 UTF-8 字符读取接口进入渲染器，即使中文、框线或符号的字节分布在两个底层管道包中，也不会显示为 `�`；Emoji 和特殊符号会使用 Windows 符号字体回退显示。
- 终端不再提供独立输入框：点击终端输出区域后直接键入命令；支持 `Enter`、方向键、`Backspace` 等终端按键。用鼠标选中文本后，可按 `Ctrl+C`、`Ctrl+Shift+C`、`Ctrl+Insert` 或右键“复制”；没有选区时 `Ctrl+C` 才会中断命令。
- 使用 ConPTY 时，`Ctrl+V`、`Ctrl+Shift+V` 和 `Shift+Insert` 会自动识别剪贴板内容：文本通过标准 bracketed paste 送入 Codex；图片保持 Windows 原始剪贴板格式，并转换为 Codex 能识别的修饰键事件，实测会显示 `[Image #1]`，不会降级成路径文本。
- 每次粘贴图片后，终端上方会出现带缩略图的 `Image #N` 附件卡片；点击即可在应用内打开可缩放的原图预览，不需要先保存路径或调用外部看图程序。
- 内置 PowerShell 会统一使用 UTF-8 输入输出，并把 `Get-Content` 的默认读取编码设为 UTF-8；项目引导也要求 Codex 在 Windows PowerShell 5.1 中显式使用 `Get-Content -Encoding UTF8`，避免无 BOM 中文文件被按 ANSI 读取。
- 终端支持鼠标滚轮和右侧滚动条回看内容，并保留最多 2000 行历史；向下滚动到底部后会恢复自动跟随最新输出。
- 当终端命令是 `codex` 时，程序会通过 Codex CLI 的初始提示参数自动执行项目引导：当前项目根目录、资料库保护规则、升级文档位置和验证/打包要求都会按当前电脑的实际路径生成。内部 prompt 始终隐藏；30 秒后会提示首次加载可能较慢，90 秒仍未完成才显示超时并提供“手动重试”按钮，收到专用完成标记后才开放输入。程序不会自动重试；旧会话的输出和计时器不会影响新会话。
- Codex 默认使用内联屏幕模式，并把高频动画输出合并为稳定的低频刷新；渲染时只修改实际变化的文字片段，不会反复清空并重建整个终端，因此持续状态动画不会造成整屏闪烁。相同画面不会重复重绘，回看历史时也不会被强制拉回底部。
- 主窗口默认宽度调整为 1240 像素，右侧终端默认宽度为 520 像素；“终端 / 信息”容器不设置最小宽度，可以向右连续拖动到完全折叠，不会在固定阈值处停止。左侧条目区不会被折叠；右侧宽度大于 0 时会保存到个人设置。
- “设置 → 外观”可切换“明亮蓝”“柔和灰”和“JetBrains 灰色”主题，主界面、条目卡片、弹窗和内置终端会同步换色。

## 使用 Codex 升级

旧版本用户只需在项目根目录对 Codex 说“更新一下这个项目”。根目录的 `AGENTS.md` 会要求 Codex 先阅读 `UPGRADE_FOR_CODEX.md`，并保护已有的资料库、简历、设置和 `tmp` 文件；升级完成后使用 `build_exe.ps1` 重新生成程序。

如果需要同步 GitHub 上的新版本，也可以在仓库根目录直接告诉 Codex“从 GitHub 更新这个项目”。Codex 会先检查本地修改和受保护文件，再获取远程代码；遇到资料库、简历或设置冲突时会停止并询问，不会用远程版本覆盖本地数据。

## 编辑快捷文本

- 快捷按钮用于快速粘贴或复制，按钮会根据键名长短自动排列。
- 同一个分组里的按钮会显示在同一个圆角框内，框左上角显示分组名。
- 点击某个快捷按钮后，窗口底部会显示当前条目，并出现“编辑”“删除”按钮。
- 默认 `Ctrl+点击` 会强制自动粘贴，适合平时关闭自动粘贴、需要填入时临时触发；这是鼠标操作，不属于可改的键盘快捷键。
- `Shift+点击` 会多选条目；多选时“编辑”按钮会变浅并禁用，“删除”会批量删除已选条目。
- 选中一个或多个条目后，点击“分组”可以调整它们所属的分组。弹窗里可以从下拉框选择现有分组，也可以输入一个新分组名来创建新分组。
- 按住条目拖动时会出现明确的插入线；卡片之间、行首、行尾和换行后的任意位置都可落下，最后一个条目也可以直接拖到最前或中间。
- 跨分组拖动会同时使用目标分组中的插入位置。也可以使用“分组”功能完成换组。
- 资源条目的右键菜单包含“打开（系统默认方式）”“打开文件夹”“打开方式”；“打开方式”会列出 Windows 已注册的 Office、WPS、编辑器等应用，并保留“选择其他应用”。普通条目仍包含“编辑”“复制”“分组”“删除”。
- 选中一个条目后按默认 `Ctrl+←` 或 `Ctrl+→`，可以在当前分组内精确移动一格；到达分组边界时不会继续移动，两个快捷键均可修改。
- 选中任意一个条目后按默认 `Ctrl+↑` 或 `Ctrl+↓`，可以把该条目所在的整个分组向上或向下移动一格；分组顺序会写回当前 JSON。多选时，只要所选条目属于同一分组也可以移动。
- 点击“编辑”会弹出小窗口修改键名、分组、条目类型和值。
- 点击“新增条目”或按默认 `Ctrl+N`，会弹出小窗口添加文本、超链接、文件或文件夹条目，并可以直接填写分组。
- 新增或编辑条目时，分组通过下拉框选择；点击“新建分组”后会立即将新分组选中。
- 文件、文件夹条目保存本地路径；超链接条目保存网址或本地资源路径。`.py`、PowerPoint、Excel、CSV、JSON 等文件都交给 Windows 默认关联打开。资源条目普通点击按设置复制或粘贴，`Ctrl+点击` 只复制路径，`Ctrl+Shift+点击` 直接打开；按一次默认 `Ctrl+Shift+E` 后再左键会在资源管理器中定位，再按一次该快捷键会取消定位模式。
- 点击“删除”会从当前 JSON 中删除该键值对。
- 搜索框会同时搜索键名和文本内容。

## JSON 应该放在哪里

如果你双击使用的是打包版：

```text
release\ResumeQuickPaste.exe
```

AI 生成的 `.json` 文件应该放在 exe 同级的 `databases` 文件夹，也就是当前项目里的：

```text
release\databases
```

如果你把 `ResumeQuickPaste.exe` 整个复制到别的地方使用，规则仍然一样：JSON 放在 exe 同级的 `databases` 文件夹。

如果你是开发者，用源码运行：

```powershell
.\setup_pyside6.ps1
.\.python-runtime\python.exe src\app.py
```

也可以直接双击 `run.bat`，它会在缺少项目运行环境时自动配置后再启动。

那么 JSON 应该放在项目根目录的：

```text
databases
```

简历 PDF、Word 或图片只给 AI 解析用，程序本身不会直接读取简历文件。程序只读取 `databases` 里的 `.json` 资料库。

## 管理多份资料库

程序会读取当前运行位置下的：

```text
databases
```

每个 `.json` 文件就是一份资料库。你可以在程序顶部新建、重命名、删除资料库，也可以直接用文本编辑器修改 JSON。

推荐使用分组 JSON 格式：

```json
{
  "groups": {
    "基本信息": {
      "姓名": "XXX",
      "邮箱": "XXX",
      "求职方向": "XXX"
    },
    "科研项目A": {
      "科研经历-科研项目A-经历名称": "XXX",
      "科研经历-科研项目A-经历角色": "XXX",
      "科研经历-科研项目A-经历详情": "论文内容：XXX。1) XXX。2) XXX。3) XXX。"
    },
    "技能证书": {
      "技能-编程语言": "XXX",
      "技能-工具": "XXX"
    }
  }
}
```

为了兼容旧文件，程序仍可以读取旧版扁平 JSON，例如 `{ "姓名": "XXX" }`。但从程序里新增、编辑或保存后，会统一写成上面的 `groups` 分组格式。

文件、文件夹和超链接使用带类型的条目格式，文本条目仍然可以直接写成字符串。旧版 `image` 类型会兼容按 `file` 类型读取：

```json
{
  "groups": {
    "作品材料": {
      "个人头像": { "type": "file", "value": "assets/avatar.png" },
      "作品主页": { "type": "link", "value": "https://example.com" },
      "作品文件夹": { "type": "folder", "value": "D:/作品集" },
      "论文 PDF": { "type": "file", "value": "D:/作品集/paper.pdf" }
    }
  }
}
```

## 放置不同岗位简历

可以把不同投递方向的简历放在：

```text
resumes_by_role
```

建议按投递场景建子文件夹，例如“数据分析岗位”“科研实习岗位”“产品运营岗位”。一份简历对应一个场景，也对应一个 JSON 资料库。

## 让 AI 从简历生成 JSON

项目根目录有：

```text
AI_PROMPT_简历生成快捷文本JSON.txt
```

你可以把这个提示词发给 AI，同时提供你的若干份简历，让 AI 按“一份简历一个 JSON”的规则生成资料库。生成后把 `.json` 文件放进对应的 `databases` 文件夹，再重启或切换资料库即可使用。

提示词会要求 AI 先询问你要解析哪些内容；你可以直接回复“默认”。默认方案是不解析教育经历、不解析任何经历时间，只解析基本信息、经历内容、技能证书等适合粘贴到投递表单里的内容。

提示词还会要求 AI 把每段实习、科研或项目经历拆成“经历名称、经历角色、经历详情”，并默认按经历或项目分组。分组名优先使用项目名、课题简称、公司/岗位短名、竞赛名，或其他能识别该经历的短名称。同一份简历不会被拆成多个岗位 JSON；多 JSON 用来管理多份不同简历。

## 重新打包 exe

如果你修改了程序代码，可以在 PowerShell 中运行：

```powershell
.\build_exe.ps1
```

脚本会使用 PyInstaller 生成：

```text
release\ResumeQuickPaste.exe
```

如果没有 PyInstaller，脚本会自动用 pip 安装。脚本会保留 `release\databases` 和 `release\resumes_by_role` 中已经存在的用户资料，只补充缺少的文件，不会用根目录示例覆盖原有条目。

当前构建产物是 x64 程序；Windows on ARM 可能通过系统的 x64 模拟运行，但不属于本项目已验证的原生 ARM64 构建范围。

## 常见问题

自动粘贴没有生效：这是某些浏览器、招聘系统或权限设置导致的。程序已经把内容复制到了剪贴板，请在输入框里按 `Ctrl+V`；也可以按住快捷按钮拖到目标输入框松开，尝试拖动输入。

找不到刚才的输入框：请先点击目标输入框，再点击快捷按钮。建议保持“窗口置顶”打开。

JSON 打不开：通常是格式错误。请检查是否使用双引号、是否有多余逗号、换行是否写成 `\n`。

`app_settings.json` 有用吗：有用，但用户不需要手动配置。它是程序自动生成的运行设置文件，用来记录窗口置顶、自动粘贴、上次选择的资料库等偏好。删除后程序会在下次启动时按默认设置重新生成。

隐私说明：本工具只读写本地文件，不上传简历或投递信息。
